fix: make the lead form actually usable, and make the file claim honest

Three gaps found in a sweep of what was still broken after the last
pass.

1. The form had no endpoint, so every submission fell back to opening
   the visitor's mail client. On a phone - which is how this audience
   reads - that loses most leads. The fallback is still there (a lead
   must never be dropped) but it is now a fallback rather than the only
   path, and the endpoint is declared in a commented config block at the
   top of the page with the three realistic options and where to get
   each. It was previously only discoverable by reading lead-form.js.

2. The offer promised "send us one list you actually market from" but
   the form had no file field, so the page asked for something it
   could not accept. Added a file input accepting csv/xlsx/xls/txt.

3. A file input would have been a trap on its own: nothing uploads it.
   Rather than pretend, the code is now explicit in all three paths.
   - the mailto body names the file and explains it did not travel with
     the email, and offers WhatsApp as the alternative
   - the mailto success message tells the visitor to attach it before
     sending
   - the fetch success message says the attachment did not come through
     and asks them to reply with it
   The success copy never claims a file was received when it was not.

Also normalised line endings in lead-form.js. Several exact-match
replacements in this session had silently failed against CRLF content
while reporting success - the same class of fault as the em-dash
corruption and the consumed </style> tag, and the reason the earlier
edits needed redoing. Every scripted edit from here normalises first and
verifies the string actually changed.

Verified: all tags balanced, all three page scripts pass node --check,
no encoding damage, zero calendar links, no orphan divs, demo warning
still present, "Most popular" still gone. Legal claims unchanged with
the invented deadline and unverified fees still absent.

STILL NEEDS A HUMAN: put a real URL in window.AGENTCY_FORM_ENDPOINT.
Until then the form works, but on a phone it will bounce most visitors
to a mail client. That is a five-minute signup at Formspree and it is
the single highest-value thing left to do on this page.
