fix: correct rowId collision, DNC Register data loss, phone normalisation

Correctness (all covered by new tests, 18/18 passing):

- CRITICAL workbook.ts: a blank RowID cell produced an empty identifier
  because `??` does not fall through on "". One registry match therefore
  suppressed EVERY blank-RowID row in the file, writing false
  do-not-contact entries into the compliance register. Row identity now
  falls back to the row index via cellText().

- CRITICAL workbook.ts: applyCleanse/applyLeadsCleanse assigned
  wb.Sheets[DNC_TAB] without adding DNC_TAB to wb.SheetNames. SheetJS
  writes only tabs listed in SheetNames, so the DNC Register was silently
  DROPPED on write: the log showed a suppression with no register entry
  surviving. Both write paths now register the tab name.

- workbook.ts: a missing expected tab silently fell back to the first
  sheet, which may be the DNC Register itself, mutating the wrong data.
  Now exits 2 and lists the tabs present; SA_DM_ALLOW_FALLBACK=1 opts
  into a read-only fallback.

- cellText() replaces the `row[idx] ? String(row[idx]) : undefined`
  pattern, which turned a cell containing "0" or "FALSE" into undefined.

- cleanse.ts normalizePhone: handle the 00 international prefix, and fix
  the 27 branch which built "0" + the full number instead of dropping the
  prefix, yielding 027821234567. This was a SILENT MISS - a registry
  entry of 0027821234567 never matched a list entry of 0821234567, so a
  consumer who had blocked us stayed live on the list.

- cleanse.ts: isMobileNumber() accepts SA mobiles only (07x/08x).
  Landlines previously passed a length >= 9 check and could be written
  to the DNC Register as false suppressions.

- cleanse.ts: blocklist header detection now scores candidates so an
  exact "Email" column beats an incidental "Mailer" column.

- CleanseResult gains alreadyDnc[]. Previously already-suppressed
  contacts were returned in `unmatched`, labelling them safe to market.

- CLI reports the already-DNC count alongside checked/matched.

Test suite added (node:test, no new dependencies) and `npm test` wired up.
README documents the failure modes.

Verified end to end via the real CLI: only the matched contact is
suppressed, the register persists across writes, prior register rows are
preserved, and a second run is idempotent (0 new matches, 2 skipped).
